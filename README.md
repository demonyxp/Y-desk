# Y-Desk

Windows 双显示器远程桌面。共享电脑当前正在使用的桌面，双方同时可见。支持自设密码和无人值守；普通模式仍需被控端确认。

**[下载安装版](https://github.com/demonyxp/Y-desk/releases/latest/download/Y-Desk-Setup-0.2.1-win-x64.exe)** · **[下载免安装版](https://github.com/demonyxp/Y-desk/releases/latest/download/Y-Desk-0.2.1-win-x64.exe)** · [全部发布版本](https://github.com/demonyxp/Y-desk/releases)

基于 Electron / Chromium 屏幕采集、WebRTC 实时视频和 Windows SendInput。没有逐帧截图轮询，也不上传录屏。**这是首个可运行版本，不承诺任意硬件、任意网络下均无卡顿。**

## 已实现

- 一次共享 1–2 个实际显示器，两路独立视频，支持并排显示、单屏切换、全屏。
- 鼠标移动、左右键、中键、滚轮、拖动、键盘组合键；支持中文文本主动发送。
- 三档画质上限和自适应传输；显示实际分辨率、解码帧率、接收码率、往返延迟及直连/中继状态。
- 固定 9 位设备码、自设连接密码（8–128 字符），区分大小写；错误尝试有频率限制。
- 无人值守支持密码验证后自动连接、托盘常驻、断网重连、重启恢复。安装版支持 Windows 登录后自启。
- 断开、失焦、网络异常时释放按键；本地 `Ctrl + Alt + F12` 紧急停止并退出。
- 自托管信令服务、WSS 部署配置、TURN 中继配置、Windows 便携版打包和 GitHub Actions 构建。

“双屏”指远端连接的两个显示器，不是两个互不影响的 Windows 登录会话，也不会凭空生成第二个虚拟屏幕。

## 快速启动（Windows 开发环境）

要求：Windows 10/11 x64、Node.js 24 LTS、系统自带的 .NET Framework 4.8。两端都运行客户端。

```powershell
git clone https://github.com/demonyxp/Y-desk.git
Set-Location Y-desk
npm.cmd ci
npm.cmd run build:native
```

终端 A 启动本机信令服务器：

```powershell
npm.cmd run server
```

终端 B 启动客户端：

```powershell
npm.cmd start
```

本机可启动两个客户端验证连接，默认服务器为 `ws://127.0.0.1:21120`，ICE 留空。**此地址只连本机，不能直接让两台不同电脑互连。** 真正远程使用需要部署下文的 WSS 服务，或使用可信 SSH 隧道。

## 两台电脑如何使用

1. 在自己的服务器部署信令及 TURN，见 [公网部署](docs/deployment.md)。
2. 两端填写同一个 `wss://你的域名`，填写部署后生成的 STUN / TURN JSON。
3. 被控端勾选屏幕，设置自己的连接密码，按需勾选“无人值守”和“Windows 登录后自动启动”，再点击“开启共享”。
4. 控制端填写固定设备码和密码，点击“连接桌面”。无人值守自动接入；普通模式仍需被控端点击“允许本次连接”。
5. 控制端点击画面开始操作。工具栏切换屏幕、画质、全屏或“仅观看”。
6. `Ctrl + Alt + Esc` 释放控制端键盘焦点；任一端可以断开。被控端也可按 `Ctrl + Alt + F12` 关闭程序。

仅发送文本时，先点击远端输入框，再展开“发送中文或长文本”。不会自动读取或同步剪贴板；“复制设备码和服务器”不包含密码。

无人值守开启后，密码和 TURN 凭据使用 Windows DPAPI 加密保存到当前用户配置目录的 `settings.bin`。关闭窗口会留在系统托盘，退出程序会停止当前连接，下一次启动可恢复。**点击“停止共享”会暂停自动恢复，直到再次手动开启共享。** 修改密码或关闭无人值守：先停止共享，再修改相应设置并重新开启。

安装版支持登录自启；免安装版在临时目录解压运行，不能用于登录自启。无人值守需要 Windows 已登录、电脑联网且未休眠；它不是 Windows 系统服务，不支持无人登录时操作登录界面。设备配置不能直接复制给其他电脑，以免复制设备身份。

## 画质与性能

| 档位 | 单屏分辨率上限 | 帧率上限 | 单屏视频码率上限 | 用途 |
| --- | --- | --- | --- | --- |
| 流畅 | 1920 × 1080 | 30 fps | 4 Mbps | 带宽较小、优先响应 |
| 高清 | 2560 × 1440 | 60 fps | 12 Mbps | 默认，文字与日常操作 |
| 原画 | 3840 × 2160 | 60 fps | 25 Mbps | 高分辨率屏幕、带宽充足 |

这些是编码上限，不会将 1080p 显示器伪装为 4K，也不保证持续 60 fps。静态桌面帧率、码率下降属正常；双屏码率上限相加，还需预留协议开销。单屏显示只改变观看布局，两路传输仍保持，可快速切回。

Chromium 自动协商双方支持的编码器并在可用时采用硬件加速。当前不强制 H.264、不保证硬编。实测统计会显示实际使用的编码器；中继延迟取决于服务器位置和链路。输入移动事件节流、视频拥塞控制和按键释放用于减少积压，不会消除物理网络延迟。

## 生成 Windows 程序

```powershell
npm.cmd run dist
```

输出安装版 `dist/Y-Desk-Setup-0.2.1-win-x64.exe` 和免安装版 `dist/Y-Desk-0.2.1-win-x64.exe`。均包含运行时和输入组件，目标 Windows 不需要安装 Node.js。未配置商业代码签名，首次打开可能出现 Windows SmartScreen 提示。不要上传 `node_modules` 或构建缓存到 Git。

推送 `main` 自动构建；推送 `v*` 标签会在构建成功后自动创建 GitHub Release，上传安装版、免安装版和 `SHA256SUMS.txt`，其他电脑可直接下载，无需下载源码或登录 Actions。

## 验证

```powershell
npm.cmd run build:native
npm.cmd test
npm.cmd run check
npm.cmd run test:e2e
```

最后一项需已登录的真实 Windows 桌面。不要同时运行端到端测试和重新编译输入组件，Windows 会锁住正在运行的 exe。

- 单元/集成测试：密码派生、设备所有权持久化、密码错误限流、确认前隔离、信令方向、拒绝/超时/断开、过期会话、无效输入、负坐标和 DPI 转换。
- 无人值守测试：错误密码拒绝、自动接入、托盘隐藏、DPAPI 保存、重启恢复、信令断线重连、停止后不再自动共享。
- 桌面测试：真实屏幕 → WebRTC → 视频解码、控制事件、中文文本、动态码率、断开清理。
- 双屏测试：在单屏机器上注入两路独立测试图，验证两路协商、并排/切屏。**模拟测试不能代替双物理屏及混合 DPI 实测。**
- 自动化运行输入组件的 dry-run 模式，验证控制事件到达原生进程，不向当前工作桌面注入真实按键。

测试截图/trace 可能包含本机屏幕，均在被 Git 忽略的 `test-results/` 中，不要公开上传。CI 运行语法检查、单元测试和打包；依赖交互桌面的端到端测试在本机执行。

## 当前边界

- 仅 Windows x64 控制端/被控端。信令可部署 Linux。
- 单个被控端同时接受一个控制端；无人值守需事先在本机显式勾选，运行时保留系统托盘图标。
- 不支持 UAC 安全桌面、登录界面、Ctrl+Alt+Delete、比本程序权限更高的窗口；不绕过 Windows 权限。
- 本地系统保留的快捷键可能由本地 Windows 处理；不承诺所有 Windows 键组合都能远程发送。
- 暂不包含声音、文件传输、自动剪贴板同步、虚拟显示器驱动、跨平台客户端。
- 本机锁屏/休眠暂停共享；无人值守在解锁/恢复后重新上线，网络中断自动重连。不会阻止用户手动锁屏或唤醒关机的电脑。
- 服务器地址必须可信。WebRTC 传输加密，但此版本没有额外的双方指纹核验；信令服务器属于信任边界。
